# TLS foundation UI

The menu order is Dashboard, Event, Participant, Fixture and Result, Game Setting Preset, Master Setting and User Management. Game Setting Preset is available as a standalone module. User Management remains disabled. The Dashboard is now the live venue control screen; see LIVE_DASHBOARD.md. The previous catalog-summary dashboard has been removed. User Management will follow TRS; operator accounts are not implemented. Paired tablet session access is described in LIVE_DASHBOARD.md.

Event uses Import Excel and Get from TRS actions. The latter displays an event list supplied by the configured external TRS transfer file, never asks the organiser to upload JSON, and does not call or lock the live TRS system. Only eligible events are displayed: registration closed, event not past/completed/archived, no fixtures and every active program meeting minimum participation. At least two entries are required for active badminton singles/doubles. No Availability column is shown. Already-imported events remain selectable; the server blocks import if the event name exists, ignoring case and surrounding/repeated whitespace. This includes collisions across Excel/TRS sources. Internal source identity remains protected. Replacement excludes its own event from the name comparison and still requires the original source identity and preparation stage P. Server import validation remains authoritative. The file-backed adapter in trs-events.ts is the current source of this list and should be replaced by an authorised TRS integration later.

Event details keep the Programs table without an embedded participant list. Each program action menu offers View Participant and View Fixture and Result. View Participant opens the existing Participant page with initial event/program filters; filters can be changed or cleared. View Fixture and Result opens the associated program’s TRS-style overview, configuration, separate draw preview and saved Bracket/Table views. No participant list expands inside Event Details. Event Details holds officials’ names; dated sessions, court selection and duration/rest belong to Fixture → Schedule, and programs advance independently; imported event/program/player identities remain read-only. Game Setting Preset is separate from both Event Details and Master Setting. Participant has a compact filtered list and a separate detail page with personal/contact data and memberships.


TRS reuse: countries.ts nationality display helper, Events.tsx filter/table markup, ParticipantDetails.tsx search/filter fields, EventEdit.tsx SectionTitle and labelled fields, and the actual ActionDropdownPortal.tsx component copied unchanged. Table, button, field, heading and action styles use TRS theme variables/CSS. The sidebar retains TRS collapse/hover behaviour and theme switching. No new UI framework is introduced.

### Action menu positioning correction

The shared `Frontend/src/ActionDropdownPortal.tsx` keeps the existing TRS menu appearance. Its viewport portal explicitly clears the stylesheet's `right: 0` and top margin, measures an intrinsic menu width and clamps its left/top position to an eight-pixel viewport margin. Menus open above their trigger when there is insufficient space below. Narrow or short viewports constrain the width/height and allow scrolling within the menu. This avoids stretching a menu between a calculated left coordinate and the stylesheet's right edge. All TLS screens using the shared portal receive the correction; TRS source and the shared theme CSS are unchanged.

Verification on 19 October 2026: frontend production build passed; actual Chrome court menus 1–4 and dashboard table menus stayed within the viewport. ## Event section panels, editable dates and themed session time — 19 October 2026

Event Details, Officials and Programs each have the exact TRS EventEdit panel container: mb-8 p-8, one-pixel theme border and the TRS layered row-hover/page background. Existing SectionTitle markup is reused. Programs remains the final section with its existing navigation actions. Event Details saves officials through Save Event Settings. Scheduling fields are saved separately in Fixture → Schedule.

The Event Details panel keeps Edit Dates visible. On each click it checks all programs; saved fixtures produce an alert instead of opening the editor. Dates have their own Save Dates/Cancel controls. Only those local dates are editable; name, sport, players and imported identity remain unchanged. The editor refreshes revision/availability on opening. The backend rechecks range, conflicts, fixture lock, participant validation and saved sessions within one transaction. Successful edits refresh displayed dates and operating context while retaining pending operating-form changes. TRS source export/package dates are not changed. Save Dates may fail if another administrator generated a fixture or changed data after opening the form.

Playing Sessions uses a shared themed TimePicker built with existing TRS Dialog, button and field styles. It has hour buttons, AM/PM, a minute field accepting 0–59 and quick-minute choices. Selected choices and confirmation use primary colour. It returns the same 24-hour HH:mm value; the existing session payload remains HH:mm:ss. Noon/midnight are converted explicitly. Cancel does not change the field, and Set Time updates the unsaved session form without triggering Save Event Settings. Native browser clock popups elsewhere are unchanged. No new UI framework or dependency was added.
