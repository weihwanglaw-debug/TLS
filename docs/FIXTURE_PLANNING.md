# Guided fixture planning — 22 October 2026

## Admin workflow

The shared workspace header contains Program Fixture List, the left-aligned program selector underneath it, sport/date/entry/format details directly below the dropdown with the current or upcoming stage beside those details and four steps: Seeding → Draw → Schedule → Fixture & Results. Internal/External is not a TLS classification and is not shown. Repeated event/program names below the dropdown are omitted. The header scrolls normally so it does not occupy the working area while reviewing long lists. Refresh preserves the selected program/step; navigating into another program starts at its next unfinished step.

1. **Seeding:** Use Seeding is on for manual or SBA-assisted seeds, off for an explicit no-seeding decision. Number of Seeds and Suggest Seeds from SBA share the row below Use Seeding. The assigned count appears once. Turning Use Seeding off hides the numeric controls, SBA action, count and seed table, while the confirmation/save action remains visible. Suggest Seeds from SBA is disabled with a short visible reason when unavailable. Suggestions do not overwrite draft assignments until Apply, and do not persist until Save. The lock notice sits within the Seeding panel. Number of Seeds and entry seeds retain their existing validation.
2. **Draw:** Configure, preview and silently swap first-draw positions. Confirm & Save is the only draw persistence action. After confirmation the same matchup-list presentation becomes Saved Draw, without swapping or confirmation controls. Continue to Schedule is primary; Apply Draw Settings to Other Programs generates opening draws for selected eligible programs using the saved format settings. Only the currently generated stage is shown in this saved matchup list. Previous rounds remain accessible in Fixture & Results.
3. **Schedule:** Match duration/rest are saved in Event Details. This is shared event planning, not isolated program planning. The program selector is disabled while scheduling; the redundant Scheduling across this event message is omitted. A prominent Playing Date selector controls that date's sessions. Each session has its own courts and eligible stage selections, allowing A in the morning and A/B in the afternoon. The repeated event/date/timezone line and the date/rest explanatory paragraphs are omitted. Select All sits at the right of each session's Programs and Stages heading. Preview/Confirm remains separate. Rest Between Player Matches means the gap after a shared player's preceding match, including across programs; planning uses estimated ends and recorded finish times when available. It may leave court capacity unused. Editing rest does not automatically rearrange existing slots; saved-slot/session/conflict validation still applies.
4. **Fixture & Results:** Available once at least one non-BYE match in the selected program has a saved date/court. Default Table View gives opponents, court, date/time, status and result in one place; Bracket View remains available. A count distinguishes scheduled and pending matches. Generating a later round cannot remove access to earlier scheduled matches. Future TBD bracket positions are not fabricated fixtures. Scheduling all current-stage matches makes this the next default destination; partial scheduling keeps Schedule as the next unfinished step but still permits viewing results.

Export Participants, Export Match Results (Selected Round), Print / Save PDF and allowed resets are grouped under Options. Table View's standalone CSV button is hidden in this workspace, and its results export respects the selected round. Distinct participant and result exports are intentional.

## Default game preset; round policy deferred

Choose an active Default in Game Setting Preset before generating any draw. At most one default is active. The Draw screen disables preview and links to the master when none exists; the backend rejects direct preview requests too, without saving anything. Every newly generated non-BYE match receives its own copy automatically. There is no Round Game Presets panel or manual preset step in Draw/Fixture & Results.

Saving a default also fills existing unassigned, unstarted, unpaired matches. Changing the default or editing master rules leaves assigned snapshots unchanged. Re-selecting a match's existing preset keeps its frozen rules even when the master was edited/deactivated. Future rounds inherit the active default when generated.

The round-wide lock/change policy is deferred. One match starting or recording a result does not lock its siblings, require uniform later overrides, or revoke their sessions. Existing started/result match protection remains: a particular match's rules cannot change once it has started or recorded a result. Clearing its result does not bypass its correction history. BYEs do not use scoring presets. Existing stored historical presetLocked flags are retained; they do not impose the removed round lock. Views report each match's actual protection state.

Existing per-match assignment APIs continue to work. Changing an unstarted paired match requires explicit confirmation and revokes only that match's code/session; other matches are unaffected. Dashboard displays assigned snapshots read-only, and started replacement tablets keep saved rules. No new manual override screen is introduced by this layout simplification.

## API and storage

GamePreset.isDefault and saved match snapshots use existing SystemSettings.LiveVenueJson and ProgramOperations.Json. No schema migration or business-data cleanup is required. Import identities, participants/clubs, schedules, officials, results and tablet details are preserved.

POST /api/tournament/preview now requires an active default for both draw-only and legacy scheduled-generation requests. Existing clients must configure that default before generation. Preview/confirmation remain separate and revision checked. Earlier-round live/match state remains preserved on confirmation.

POST /api/presets/assign uses its matchId target again, rather than changing the entire round. The additive confirmRoundChange field is retained for compatibility as the confirmation for replacing that particular match's binding; its historical name does not imply a round-wide change. Existing same-preset pairing/result calls keep frozen rules. Trying to change a started/result match is rejected; a started sibling does not block an unstarted target. All mutations retain serialized transactions, audit/revision and live-version guards.

## Apply draw settings to other programs

From a saved Draw, Apply Draw Settings to Other Programs opens one dialog containing other programs within that event. Select All selects eligible rows only. Disabled rows show the reason: seeding not reviewed, draw already exists, inactive program, unsupported sport/format, missing active default preset or incompatible settings. Confirm & Generate creates and saves the selected opening draws directly; there is no additional preview. The organiser stays on the source draw and receives one completion alert.

Only format, group count and advancement count are reused. Each target retains its own reviewed seeding mode, chosen seed count, assignments, entries and rankings. Source pairings are not copied. New matches receive the current active default preset and unique event match numbers, with no date, time, court or official assignment. Existing draws are never overwritten and later rounds are not generated by this action. Current fixture support is badminton singles/doubles. Group sizes and match-count limits are checked for each target; one batch permits at most 2000 new matches.

GET /api/tournament/{eventId}/apply-draw-settings?sourceProgramId={id} returns the current revision, source settings and candidate reasons without changing records. POST /api/tournament/apply-draw-settings accepts revision, eventId, sourceProgramId and programIds and returns revision/count. Local-admin access, serialized SetupStore transactions and audit action APPLY_DRAW_SETTINGS apply. Confirmation rechecks every target and revision; any failure rolls back the whole batch. The dialog refreshes eligibility after failure and clears selection, requiring a new deliberate confirmation.
