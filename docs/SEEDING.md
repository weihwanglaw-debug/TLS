# Separate Seeding stage — 21 October 2026

## Admin flow

Fixture and Result lists a clickable Seeds / Participants column: assigned seed entries over distinct active participants (for example 2/8, 0/8 or NA/8). NA requires a confirmed no-seeding decision. The numerator counts entries, including pairs/teams; the denominator counts individual people. Review/lock details remain accessible. Stage, Draw and Schedule columns distinguish the current or upcoming stage, Pending draw/Draw generated and Pending/Partly scheduled/Scheduled. Continue opens the next unfinished workspace step. An unsaved preview remains Pending; resetting the whole draw returns it to Pending. Generated does not imply that dates, times or courts have been assigned. The former Preparation column is removed; underlying minimum-participation and supported-format validations remain unchanged.
The dedicated page uses existing TRS panels, toggles, table, buttons, theme colours and alert dialogs. Use Seeding is on when manual or assisted seeds are enabled and off for no seeding. Suggest Seeds from SBA is an action button, with a short unavailable reason. Manual inputs are directly available when Use Seeding is on. The assigned count appears once in the Seeding panel. There is no Restore Imported Seeds action. Imported/saved seeds load initially; Cancel/Back do not write.

Number of Seeds is a compact numeric field shared by manual and assisted seeding. It accepts 1 through the active entry count and is initially populated from the saved count or highest imported seed. Assigned values must be unique integers from 1 through the chosen count. Reducing the count never silently removes assignments: invalid values block saving until corrected. Partial assignments are permitted; the list shows the actual assigned count. Turning Use Seeding off clears the draft and hides the seed-count/SBA controls, assigned count and seed table. Confirmation saves mode N with count 0. Seed fields remain 80px wide.

SBA columns appear only with assistance selected. When unavailable, a short visible message below the toggle distinguishes missing SBA IDs, missing exact category, unmatched entries and unsupported sport/entry type; there is no SBA tooltip. Enabled seed fields use the theme primary border and readable background/text, with a primary focus ring. No-seeding, busy and locked fields use a muted disabled background/text in both themes. These styles are scoped to the Seeding panel. Assistance is disabled unless at least one eligible badminton singles/doubles entry matches the exact local category and its complete SBA IDs. Teams and other sports retain manual/no-seeding options. Team rows show a shared imported club/school/company when every member has the same nonblank value, otherwise the imported entry/Group ID. A distinct entry label remains visible to distinguish teams from the same organisation. Expand a row to view the original roster, including on a locked draw. No club master lookup rewrites participant club text.

SBA suggestions are available only if the exact program name matches a category containing local SQL ranking rows. Case, punctuation and spaces must match; SQL trailing-space padding is explicitly excluded by an ordinal comparison after query filtering. No manual category override or external ranking-file/API dependency remains. Singles match one SBA ID with a singles record. Doubles require two distinct nonblank IDs matching both partners, in either order. IDs are trimmed/case-normalized for lookup, while imported values remain unchanged. Missing IDs never fall back to name matching or a singles record for a doubles pair.

Choose how many seeds to propose. Suggestions follow accumulated points descending, then ranking and entry ID for deterministic ties. The preview lists proposed seed numbers and unmatched entries, without saving or changing the draft. Apply Suggestions to Draft explicitly replaces draft assignments; unmatched entries become unseeded and may be assigned manually. A zero-match suggestion cannot be applied. Save Reviewed Seeding persists only after review. Local ranking replacement after loading/suggesting returns a conflict at save, rather than silently changing the referenced data.

## Persistence and protection

GET /api/seeding/{programId} returns the program, active entries/players, imported and operational seeds, review/lock state and current local ranking match information. POST /api/seeding/{programId}/suggest takes revision, seedCount and rankingFingerprint and returns an unsaved proposal. PUT /api/seeding/{programId} takes revision, complete active-entry seed dictionary, mode, seedCount and optional rankingFingerprint. seedCount is additive and optional for older clients, which infer the highest seed value. Modes are short codes M (manual/imported), N (no seeding), S (SBA-assisted). The save requires an active singles/doubles/team program, every active entry exactly once, unique integral seeds within the chosen count (itself bounded by entry count), current revision and no saved draw. N requires all seed values to be null.

Operational assignments, SeedsReviewed, SeedCount and SeedingMode are stored in the existing ProgramOperations JSON. SBA saves also record category, ranking snapshot and retrieval timestamp. Snapshot verification is repeated inside the existing serialized SetupStore transaction, alongside audit/revision persistence. Updating ranking masters cannot change already saved seeds or snapshots. Saved-draw views show the captured ranking rows. Resetting a permitted unplayed draw makes seeding editable again. Imported event/program/player identities, participant club text, imported entry seeds and import metadata are not rewritten by operational seeding.

No database migration or new table/column is needed. Existing plans without SeedingMode remain readable: SeedsReviewed and existing operational/imported values determine status. Previously confirmed seeds remain confirmed. Imports with no stored program plan remain Not reviewed until the admin confirms them.

## Draw integration and compatibility

Draw configuration has no seed inputs, participant seed table or category selector. It consumes saved reviewed seeds. Save seeding and use Continue to Draw in the guided workspace; draw preview requires saved review. The persistent flow bar provides earlier-step navigation. Changing format does not clear seeds. Courts/times are now separate under Fixture and Result → Schedule Event; see SCHEDULING.md.

The existing first-draw preview API remains backward compatible with older clients supplying settings plus a complete seed dictionary. Current UI sends settings only and requires persisted reviewed seeds. Legacy /api/trs/rankings reads local SQL. Legacy ranking-snapshot calls enforce exact Program Name, local SQL and the existing draw lock; arbitrary category selection is rejected. Trs:RankingFile and Trs:BaseUrl no longer provide seeding data. TRS event-file transfer remains available and unchanged.
